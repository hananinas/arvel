## Recording boundaries

- The **0:15–1:40 hardware interval requires the physical board throughout**. Software-only shots cannot stand in for it. The opening, restart/recall and denied-action shots also need authorized hardware.
- Web login, Settings, history export and source presentation can be recorded now against isolated local fixtures. Their narration above explicitly labels that evidence. For a final live-device recording, replace the fixture-specific sentence only after the corresponding behavior has actually been exercised; do not merely remove the label.
- The host test uses production SQLite/storage code and a temporary filesystem, not a cloud model or SD card. Its 80-ID result is not a Codex longevity result. If a test run is edited for time, say so.
- Confirm a typed chat with a tool call through the device on the DeepSeek preset before filming; the 2026-10-30 check was a direct API request from the build host, not the device path.
- A final architecture shot may report the measured app size/free slot space from [submission verification](submission-verification.md). It must not relabel app-slot space as runtime heap headroom or quote vendor model latency as measured Arvel latency.
- No GPU deployment, device operation, search-provider request, video recording or publication was performed to create this storyboard. A public English-language video under three minutes remains an owner deliverable after the gates above pass.
