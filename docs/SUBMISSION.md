# Arvel — submission draft

Draft reviewed against local source, committed history and host verification on 2026-10-19. This is not a claim of completed hardware/cloud acceptance or cleared publication rights.

## What Arvel is

Arvel is a desk companion for the Waveshare ESP32-S3-Touch-LCD-3.49. ESP-IDF firmware runs its touchscreen, audio lifecycle, device controls and agent integration. A SvelteKit owner web app provides authenticated settings, conversation status, source links and SD-history management. Conversation inference runs remotely; the ESP32 does not run a Nemotron model locally.

The device supports a text pipeline, experimental direct Codex subscription voice and an adapter for NVIDIA-NemotronLabs-VoiceChat-11B native speech. A selected transport is explicit: an unavailable service does not silently route a request to another model. The native NVIDIA deployment has not been GPU-tested here.

**Submission inference deployment:** DeepSeek V4.1 Flash (`deepseek-ai/DeepSeek-V4.1-Flash`) on Nebius Token Factory, `https://api.tokenfactory.us-north1.nebius.com/v1/chat/completions`, through the text pipeline's OpenAI-compatible adapter. Settings offers it as the **Nebius · DeepSeek V4.1 Flash** preset.

This is a text model, not an NVIDIA model and not native speech. On 2026-10-30 a direct request from the build host, using the project's Token Factory key and a two-tool schema, returned both expected tool calls in one reply in 0.81 s. That is one API-level check, not a device-path, latency or availability measurement. The NemotronLabs VoiceChat adapter is unchanged and still not GPU-tested; Nebius also lists `nvidia/Nemotron-3.5-Super-VL` for this key, which passed the same check in 1.19 s but is not the selected model.

## Architecture

- **ESP32 / ESP-IDF 5.5.3:** LVGL touchscreen, physical microphone/speaker, Wi-Fi, owner HTTP API, speech lifecycle and device-tool adapters.
- **Rust runtime on the board:** `unravel-agent-runtime` runs the agent loop. The firmware registers 13 standard tools: `manage_timer`, `manage_notes`, `calculate`, `convert_units`, `get_weather`, `search_web`, `get_device_status`, `get_battery`, `scan_wifi`, `set_display`, `set_sound`, `set_profile`, `search_history`; opt-in builds add `sandbox_run_code` and `sandbox_operation` for Nebius Sandboxes. Not all are local-only: weather, search, sandbox and cloud inference require their respective services. Up to three consecutive read-only calls from one model reply run concurrently; effectful tools, Wi-Fi scan and history search stay sequential.
- **Rust/C++ boundary:** `components/agent_runtime` binds the Rust runtime through an in-process C ABI. C++ supplies model transport and tool callbacks; it is also reusable independently of this device UI. Host integration checks exercise that boundary.
- **Owner web app:** SvelteKit compiles to static assets. The firmware serves them; Vite can proxy development requests to a selected board. Home's state preview is a drawing of reported state, not a physical-screen capture. Web voice controls operate the board microphone, never the browser microphone.
- **Owner-held archive:** SQLite on SD stores finalized text, tool evidence and sources, not raw audio by default. The durable tool ledger reuses completed results, rejects identity/argument conflicts and marks unfinished calls unknown after recovery. This prevents automatic replay; it is not an exactly-once guarantee across physical power loss.
- **Nebius Sandboxes (opt-in):** the board calls the Sandboxes REST API directly to run user-requested Python/shell remotely. Submission requires ready durable SD storage. An earlier permission check returned no Sandboxes permissions for the project; the device's SD history for 2026-10-29 16:15 records a real run: asked to run `print(2+2)`, `sandbox_run_code` and two `sandbox_operation` calls completed with state succeeded, and Arvel reported output `4`, exit code 0, for operation `01a1883a-d6d1-7690-bde5-3efece270a96`.

There is no device shell, Git executor or generic MCP execution surface.

## Setup and build

Requirements: ESP-IDF 5.5.3, the Espressif Xtensa Rust toolchain named `esp`, Cargo/rustup, Node.js/npm, Python 3, host C/C++ compilers, CMake, pthreads and OpenSSL development headers/libraries. Managed cJSON and Cargo dependencies must already be available for offline host checks. Fresh-machine toolchain/dependency provisioning needs network access and was not repeated during the offline submission pass.

Use [README build and board selection](../README.md#build-and-board-selection) for provisioning, the standard `export.sh` option and menuconfig board-revision guidance. The working EIM alternative on the build host is below. Run in Bash; use the activation path generated by your EIM installation if different.

```sh
export PATH=$HOME/.bun/bin:$HOME/.local/bin:$HOME/.nix-profile/bin:$PATH
. "$HOME/.espressif/tools/activate_idf_v5.5.3.sh"
function idf.py() {
    "$IDF_PYTHON_ENV_PATH/bin/python" "$IDF_PATH/tools/idf.py" "$@"
}
idf.py --version
rustc +esp --version
```

EIM supplies an interactive alias; the function makes noninteractive Bash deterministic. In the read-only verification sandbox its optional final IDE-selection sync returned 1, although the environment was populated and the version/build commands succeeded. The standard installer path failed on this host in round 1 because of an EIM Python/tool-root/constraints mismatch; it remains valid guidance for conventional installations, not a verified path on this machine.

From the repository root:

```sh
npm --prefix interface ci
```

For a fresh private configuration and board selection, follow the README's menuconfig instructions; do not overwrite an existing `sdkconfig.local`. With an existing configuration, the verified build-only command is:

```sh
idf.py -D SDKCONFIG=sdkconfig.local -D SDKCONFIG_DEFAULTS=sdkconfig.defaults build
```

The round-2 and round-3 firmware builds ran with networking isolated, physical devices hidden and `sdkconfig.local` mounted read-only. npm installation used its local cache in offline mode. No flash, monitor, erase or provider request was performed. The build image can contain credentials and is not a public submission attachment.

## Verify without a device

From the repository root:

```sh
npm --prefix interface run check
(cd interface && node --test test/*.test.mjs)
npm --prefix interface run build
bash components/agent_runtime/test/run.sh
bash components/ai_chat_bsp/test/run.sh
bash components/codex_auth/test/run.sh
CC=gcc bash components/web_auth/test/run.sh
CC=gcc CXX=g++ bash components/conversation_store/test/run.sh
cmake -S components/speech_tts -B /tmp/arvel-speech-host
cmake --build /tmp/arvel-speech-host --target speech_live_protocol_test speech_tts_smoke -j 4
/tmp/arvel-speech-host/speech_live_protocol_test
/tmp/arvel-speech-host/speech_tts_smoke /tmp/arvel-speech.pcm
```

The system GCC selection matters on this host: the default Nix compiler did not find OpenSSL headers for the storage suite. Speech smoke writes PCM to `/tmp` rather than an audio device. Commands require installed/cached dependencies; they do not establish provider access, TLS interoperability with real services or physical acceptance.

For web development, run the README's `UNRAVEL_DEVICE_URL=... npm run dev -- --host 127.0.0.1` command from `interface` with the actual board origin. Round 2 checked startup and HTTP 200 using `http://127.0.0.1:9` as a dummy origin only. Real login needs a physically approved owner account. Use only a trusted LAN; the owner web API uses HTTP, not HTTPS.

## Round 4 — parallel tools, background scenes and Nebius preset (2026-10-30)

- **Runtime:** the C++/Rust boundary now runs up to three consecutive parallel-safe (read-only) tool calls concurrently instead of one at a time. Model calls and effectful tools still wait for every earlier callback, so a timed-out call never overlaps the next. Per-call policy state replaced two shared globals, and the in-memory duplicate-call ledger has its own lock.
- **Background scenes:** `set_display` resolves a scene by id or display name, ignoring case and separators, and an unknown name returns the valid ids. The tool description names it the background/wallpaper; the system prompt asks for a direct setting call and batched independent lookups.
- **Nebius preset and display:** Settings adds the DeepSeek V4.1 Flash preset above. The device status row and web previews no longer show the fixed `gpt-live-1-codex` transport model.
- **Host evidence:** agent-runtime suite passed (6 Rust tests and the C++/Rust integration executable), including a new check that two parallel-safe tools overlap and a following serial tool waits for them; that check fails with parallelism disabled. ai_chat_bsp host suite passed. Svelte check 0 errors / 0 warnings; interface tests 27/27 passed. ESP-IDF build with `sdkconfig.local` exit 0: `0x50ef90` bytes, `0xf1070` (16%) free in the 6 MiB slot.
- **Device evidence:** the parallel-tools build (before the label and preset changes) was app-only flashed at `0x10000` after reading a matching partition table and `ota_0` selection; the write hash verified and boot reached Wi-Fi, web server and native tool registration without panic, with 112,723 bytes internal heap free after init. Concurrent-tool memory headroom under live voice is not yet measured.

## Current limitations and release checklist

- **Inference:** the selected DeepSeek-on-Nebius deployment has one direct API tool-call check (above); typed chat through the device, latency on the board and provider availability during judging are not yet measured. It is not NVIDIA inference and not native speech. Codex live access also depends on account eligibility. Do not present an adapter, settings choice or health response as successful model inference.
- **Physical acceptance:** display/touch, microphone/speaker, interruption, long-call/Opus watchdog behavior, restart/SD-fault continuity, concurrent-tool internal-RAM headroom and runtime resource headroom still need authorized hardware runs. The 64-ID live-voice ceiling is unchanged pending that baseline. The echo guard is not acoustic echo cancellation.
- **Privacy/security:** owner HTTP is LAN-only; passwords, cookies and API keys can be exposed on the LAN. Credentials in flash/NVS and SD history are unencrypted. Selected messages/audio/tool context leave the board for configured cloud services. Rotate credentials previously exposed in Git; never record sign-in codes, secrets or household transcripts in the demo.
- **Dependency diagnostics:** the focus-trap package's missing Svelte exports condition remains visible. Firmware vendor mixed-enum deprecation and libc executable-stack warnings remain. No warning suppression or node_modules patch was used.
- **Rights — unresolved:** original Arvel integration is AGPL-3.0-only, not a blanket license for every bundled component. Resolve Espressif Modified-MIT versus linked GPL/AGPL compatibility, NVIDIA container/model/public-demo/judging permissions, and artwork/branding/footage rights before distributing combined firmware or publishing a demo. Check required third-party notices and source obligations.
- **Repository publication:** `THIRD_PARTY_NOTICES.md` and `scripts/VOICECHAT_DEPLOYMENT.md` existed only as untracked files during this pass and were deliberately not added or changed. Existing README links to them therefore do not make them available in a clean checkout. The owner must resolve their publication/rights status; this draft does not substitute for their contents. The ignored hackathon plan is not a committed deliverable.
- **Judging:** arrange limited, safe access without household credentials; verify current entrant/rules eligibility, deployment cost limits and free judging availability. The planning record calls for access through December 15, 2026, 12:00 Pacific, but those arrangements and current rules were not independently verified here. The storyboard is a draft, not a completed public video.
